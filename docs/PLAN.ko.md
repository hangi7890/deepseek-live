# DeepSeek Live 실행 계획과 완료 기준

작성: 2026-09-16. 작업 방식: **계획 → 작은 목표 실행 → 증거로 검증 → 통과한 뒤 다음 단계**.

## 최종 목적

다른 사람이 저장소를 복제해 실제 음성 대화를 사용할 수 있고, 정확한 기술 설명·재현 가능한 데모·기여 경로를 갖춘 공개 프로젝트를 만든다. 그 결과로 자발적인 사용자 관심과 기여를 얻는다.

코드 공개와 실제 제품 검증을 구분한다. GitHub Star 수는 관찰할 외부 성과이지 개발 완료를 증명하는 지표가 아니다. 목표 Star 수와 기한은 아직 정하지 않았다. 숫자를 임의로 설정하거나 달성을 보장하지 않는다.

현재 기반은 브라우저 STT → DeepSeek 텍스트 스트리밍 → 브라우저 TTS이다. GPT-Live와 동일한 네이티브 full-duplex 모델이라는 주장을 하지 않는다. 공개 연구의 구조적 장점을 단계적으로 반영한다.

## 진행 규칙

1. 각 단계의 시작에 산출물과 통과 조건을 정한다.
2. 작업은 검증 가능한 작은 변경으로 나누며 관련 테스트를 먼저 정한다.
3. 테스트 결과, 실행 환경, 커밋 또는 재현 절차를 증거로 남긴다.
4. 실패하면 원인을 수정하고 해당 검증을 다시 한다. 문서 작성이나 코드 존재만으로 기능 완료를 선언하지 않는다.
5. 외부 조건이 필요한 항목은 대기로 표시한다. 그 조건에 의존하지 않는 준비 작업은 계속하되, 미검증 단계를 완료 처리하지 않는다.
6. 단계 통과 후 다음 단계로 진행한다. 작업 보고는 완료한 목표, 증거, 남은 문제, 다음 목표 순서로 한다.
7. 사용자가 별도로 요청하지 않은 커뮤니티 게시·메시지 발송은 하지 않는다. 공개용 소개문과 자료는 준비할 수 있다.

- `DEEPSEEK_API_KEY`는 사용자가 로컬 `.env`에 설정해야 한다. 키를 채팅·GitHub·브라우저 Settings에 넣지 않는다.

## 단계 1 완료 증거

실제 `public/app.js`를 결정적 DOM·음성·타이머·네트워크 대역과 함께 실행하는 테스트 9개를 추가했다. 이전 인식기의 늦은 오류가 새 인식기를 중단하는 문제와, 취소한 발화의 늦은 오류가 새 상태 알림을 덮어쓰는 문제를 수정했다. 이전 커밋의 앱으로 테스트했을 때 해당 두 항목이 실패했고, 수정 후 전체 25개가 통과했다. 환경과 한계는 [VALIDATION.md](VALIDATION.md)에 기록했다.

## 다음 작업: 단계 2 및 독립적인 사용성 준비

사용성 준비에서 토큰 누락·분석 개수 제한·설정 연결 실패 시 초안이 사라지던 동작을 고쳤다. 실패한 답변에는 명시적인 재시도 버튼을 제공하며 새 초안은 덮어쓰지 않는다. 모바일 전송 버튼은 44px, 입력 글꼴은 16px로 확인했다. 현재 자동 테스트는 30개다. 공개 저장소를 새로 복제하고 패키지 설치 없이 문서의 `npm start`를 실행하는 smoke 검증을 통과했다. Node 22/24와 Docker 검증은 [CI 실행 기록](https://github.com/hangi7890/deepseek-live/actions/runs/35092667370)에 남겼다.

실제 API 키의 설정 여부를 확인한 뒤 일반/심층 대화를 검증한다. 키가 없으면 실측 단계는 대기로 유지하며, 키 없이 가능한 설치·오류 안내·모바일 검수를 진행한다. 실제 마이크 시험과 재현 가능한 음성 데모는 건너뛰거나 완료로 바꾸지 않는다.

최종 제품 검증과 자연스러운 커뮤니티 성장에는 외부 조건이 있다. 그 조건이 남으면 남아 있다고 보고하며, 초기 공개본을 최종 목적 달성으로 취급하지 않는다.
